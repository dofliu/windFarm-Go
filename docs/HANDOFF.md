- **改動 app 程式碼/資產時,把 `public/sw.js` 的 `CACHE = "wfg-cache-vN"` 版本號 +1**(避免更新後舊快取殘留造成空白;目前 **v17**)。純文件變更不需動。
- 新功能務必在 `test/run.mjs` 補對應測試(以純資料/reducer 為主);新 reducer action 也加進 fuzz 動作池(`randomAction`)。純函式引擎(如 `exam.ts`)最好給可決定性種子測試。
- **新增彈窗/鍵盤互動流程時,比照 `test/e2e.mjs`(2026-09-01 新增、2026-09-02/09-03 擴充)補一筆 Playwright 斷言**,而非只在開發 session 內一次性截圖驗證後就丟棄——這樣行為才會被 CI 的 `e2e` job 持續把關,不必每次改動都重新手動走一遍。
- **`checkModalFocusTrap()`(共用 focus trap 測試輔助函式)只驗證 focus 不逃逸出面板,不驗證確實走訪了哪些元素**——若某個本該可聚焦的元素其實漏了 `tabIndex`(如 2026-09-08 發現的 `ConstructionModal` 選項卡缺口),Tab 只會在其餘元素間打轉,一樣「不逃逸」而空綠通過,測不出這處迴歸。要驗證「特定元素確實在 Tab 序列中」時,改用逐步比對 `document.activeElement` 的 `role`/`aria-label`/`textContent`(見 `test/e2e.mjs` 的「風場建置番外篇彈窗」測試),不要無腦沿用 `checkModalFocusTrap()`。
- **測試涉及 UI 端自行擲骰的分支(如 `rush()` 的 `Math.random() < RUSH_RISK`)時**,用 `page.evaluate` 在觸發前暫時覆寫 `Math.random` 回傳固定值鎖定想測的分支,動作後立即還原,避免真實機率造成 CI 測試非決定性(見 2026-09-03 加班搶修分支測試)。跨日呼叫 `advance()`(如 `REPLAN_RETURN`)則連海象都會用真實 `Math.random()` 重擲,目前尚未納入這套覆寫,是 `#carry` 分支還沒補測試的原因。
- **測試流程中若會觸發 `say()` 對話框**(`DialogueLayer`,全螢幕 `zIndex:50` 遮罩,會攔截點擊),用 `test/e2e.mjs` 已有的 `dismissDialogue(page)` 輔助函式逐句點掉(第一下補完逐字動畫、第二下換下一句),不必臆測對話句數;`DialogueLayer.tsx` 根 `div` 已加 `data-testid="dialogue-layer"` 供辨識。
- **視覺驗證流程(一次性截圖 debug 用;正式迴歸請走 `npm run e2e`)**:`npm run build` → 把 `dist/` 以 symlink 掛成 `<serve>/windFarm-Go/`(base 是 `/windFarm-Go/`)→ `python3 -m http.server` 提供(比 `vite preview` 在無頭瀏覽器下穩) → 用 **`playwright-core`** + 預裝 Chromium(`executablePath: /opt/pw-browsers/chromium-1194/chrome-linux/chrome`,`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`)截圖;`newContext({ serviceWorkers: "block" })` 避免 SW 干擾。guest 登入點「訪客試玩」;背景模式存於 `localStorage['wfg-mode']`(sim/real/comic)。`test/e2e.mjs` 本身用 Node 內建 `http` 自製靜態伺服器(不需 symlink/python),`playwright`(非 `-core`)套件已含 CLI,CI 用 `npx playwright install --with-deps chromium` 取得瀏覽器。
- 指令:`npm test`(單元 167)、`npm run sim`(平衡)、`npm run stress`(併發)、`npm run build`、`npm run typecheck`、`npm run e2e`(Playwright UI 迴歸 38 項,**需先 `npm run build`**)、`npm run live-check`(線上後端;沙盒代理擋 script.google.com,需本機跑)。
- **內容資料交叉驗證**:新增/改故障(`incidents.ts`/`faults.ts`)、備品(`data.ts`)、任務(`tasks.ts`)時務必檢查:`part` 是否存在於 `PARTS`、每個備品是否有消費端(避免孤兒)、`discipline` 是否與 UI 一致、`minTier` 是否形成「故障可見但備品鎖住」的閘門矛盾——`test/run.mjs` 已含這套不變式測試(如 incident.part tier ≤ incident tier)。
- **模擬器蝴蝶效應(已知、非迴歸)**:`advance()` 的倉儲折舊迴圈依 `inventory` 物件的**插入順序**逐一擲骰;只要備品 id 集合或順序變,固定種子(`mulberry32(20260622)`)重播的隨機序列就整段分岔,`npm run sim` 絕對數字隨之跳動。回測看**相對排序與梯度**即可。
